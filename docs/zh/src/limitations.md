# 边界与限制

库对自己覆盖什么毫不含糊。这一章列出边界，宿主可以在问题出现之前就规划好绕行方案。

## 过滤这条轴没有测量

探测读的是端口序列，量的是映射。过滤需要改端口请求或第三方回声，探测序列里只有绑定请求，所以 `NatInfo.filtering` 恒为 `Unknown`。策略只消费映射类别，对称对的算术公开自己的假设：两端都是地址相关过滤，即 CGNAT 的常见形态。对称对的两侧都按地址端口过滤时，碰撞概率随端口空间平方下降，有限预算买不到任何东西。预期遇到这种形态的宿主从一开始就该规划中继。

估算值是模型值。真实 CGNAT 的端口空间各有不同，模型读的是对端观测到的区间，真实空间更宽时实测命中率可能低于估算。

## 一场会话一次尝试

一场会话就是一次尝试。重试循环、并行尝试、中继降级都归宿主。[快速上手](getting-started.md) 列了清单，报告提供决策所需的事实：成功率估算、发包计数、各阶段耗时。

## 信任止步于桥

数据面唯一的凭证是 128 位 nonce，信令面信任宿主信道交付的一切。库不带认证和加密。宿主在帧进桥之前完成对端认证和重放拒绝，交付套接字上的业务协议自带加密。

## IPv6 保持极简

探测收集全局 IPv6 地址，Direct 段优先尝试 v6 对，全局地址不需要 NAT 配合。除此之外没有 IPv6 NAT 模型，v6 用例在回环上验证，真实全局地址下的路由与防火墙行为走的是通用的快速失败路径。

## 脉冲覆盖集固定

生日脉冲的端口列表每次尝试抽一次，扫掠重复同一份覆盖集。头几轮扫过之后的残余脱靶会一直脱靶到预算耗尽。每轮重抽覆盖集、让后续轮次有机会补回早期脱靶，属于未来的工作方向。

## 缓存由宿主判断

`with_cached_nat` 拿宿主给什么就信什么。构造器把值钳制到线上限内，新鲜度问题留在宿主手上，因为只有宿主知道网络变没变。
