# 边界与限制

库对自己覆盖什么毫不含糊。这一章列出边界，宿主可以在问题出现之前就规划好绕行方案。

## 过滤这条轴需要发现服务器

探测用 RFC 5780 改址请求测试测量过滤，而只有通告 OTHER-ADDRESS 的发现服务器能应答这些测试。服务器列表只讲普通 RFC 5389 的宿主保持 `FilterClass::Unknown`，策略把它读作宽松情形：对称对的算术假设两端都是地址相关过滤，即 CGNAT 的常见形态。对称对的两侧都按地址端口过滤时，碰撞概率随端口空间平方下降，有限预算买不到任何东西；有测试作答时，配对在任何套接字打开之前就以 `Unpunchable` 告终，而不是把预算烧在一场擦边球上。预期遇到这种形态的宿主从一开始就该规划中继。

估算值是模型值。真实 CGNAT 的端口空间各有不同，模型读的是对端观测到的区间，真实空间更宽时实测命中率可能低于估算。

## 两个模糊锥形读数遇上严格过滤

只有一个应答服务器 IP 时读出的锥形，可能是地址相关映射透过一条映射看到的样子，所以两个这样的读数会走 SymProbe，其应答侧喷射写的是对端观测到的端口。当真实形态是两个地址相关映射、而对端按端口严格或地址严格过滤时，射手脉冲死在对端的过滤上，喷射又叫不出对端新开的打洞端口。探测自己的过滤测试解不开这个模糊：它量的是过滤轴，不是第二台服务器 IP 才能定的映射轴。在这类 NAT 后面只提供单地址服务器列表的宿主，该规划中继或第二台发现服务器。

## 一场会话一次尝试

一场会话就是一次尝试。重试循环、并行尝试、中继降级都归宿主。[快速上手](getting-started.md) 列了清单，报告提供决策所需的事实：成功率估算、发包计数、各阶段耗时。

## 信任止步于桥

数据面唯一的凭证是 128 位 nonce，信令面信任宿主信道交付的一切。库不带认证和加密。宿主在帧进桥之前完成对端认证和重放拒绝，交付套接字上的业务协议自带加密。

## IPv6 保持极简

探测收集全局 IPv6 地址，Direct 段优先尝试 v6 对，全局地址不需要 NAT 配合。除此之外没有 IPv6 NAT 模型，v6 用例在回环上验证，真实全局地址下的路由与防火墙行为走的是通用的快速失败路径。

## 脉冲覆盖集固定

生日脉冲的端口列表每次尝试抽一次，扫掠重复同一份覆盖集。头几轮扫过之后的残余脱靶会一直脱靶到预算耗尽。每轮重抽覆盖集、让后续轮次有机会补回早期脱靶，属于未来的工作方向。

## 缓存由宿主判断

`with_cached_nat` 拿宿主给什么就信什么。构造器把值钳制到线上限内，新鲜度问题留在宿主手上，因为只有宿主知道网络变没变。
