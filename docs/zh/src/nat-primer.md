# UDP 打洞的原理

两台藏在 NAT 后面的主机想直接收发 UDP。一个数据报想穿过 NAT，前提是 NAT 里已经有一条放它通过的映射。打洞做的事情，就是让两端的映射在同一时刻被有意地造出来。这一章从 NAT 的基本行为讲起，一步步走到为什么一对恶劣的 NAT 会打不通。

## NAT 在做什么

家用路由器用一个公网 IPv4 地址服务整个内网。当 `192.168.1.10:5000` 的笔记本向 `1.2.3.4:3478` 发包时，路由器把源地址改写成自己的地址加一个新端口，比如 `203.0.113.7:61000`，并把这对地址记进转换表：

```text
内网 192.168.1.10:5000  ↔  公网 203.0.113.7:61000
```

这条表项就是一条映射。笔记本的后续流量让映射保持存活，匹配这条映射的入站数据报会被送回笔记本。转换表的容量有限，这也是打洞库要盯紧自己建了多少条映射的原因之一。

## 映射和过滤是两个独立行为

NAT 的行为分成两条轴，打洞对它们的处理是分开的。

**映射**决定一个出站流量拿到哪个公网地址和端口。

| 映射类别 | 规则 |
|---|---|
| 端点无关（endpoint-independent） | 每个套接字一条映射，发往任何目的地都复用 |
| 地址相关（address-dependent） | 每个目的地址一条映射 |
| 地址端口相关（address-and-port-dependent） | 每个目的地址加端口一条映射 |

**过滤**决定哪些入站数据报可以通过已有的映射进来。

| 过滤类别 | 规则 |
|---|---|
| 端点无关 | 任何来源都能发进来 |
| 地址相关 | 套接字写过的来源地址可以发进来 |
| 地址端口相关 | 只有套接字写过的那个确切地址加端口可以发进来 |

**锥形（Cone）NAT** 做端点无关映射，一条映射服务所有目的地。**对称（Symmetric）NAT** 按目的地分配，同一套接字发往不同服务器会拿到不同端口。过滤类别和这个划分是交叉的。最常见的家用路由器做端点无关映射，同时按地址端口过滤，老文献把这种组合叫端口受限锥形。

## 反射地址

NAT 后面的主机只看得见自己的内网地址，对自己在公网上的样子一无所知。STUN 服务器能告诉它。主机向服务器发一个绑定请求，服务器把收到的源地址原样回告，例子里就是 `203.0.113.7:61000`，这就是**反射地址**。

反射地址是打洞双方最先交换的事实。它描述的是某一个具体套接字，而 NAT 按套接字分配端口，所以每个策略都要重新确认自己瞄准的端口。这一点后面会反复出现。

## 会合问题

打洞要求双方都向对方的反射地址发包，可谁一开始都不知道对方的反射地址，所以双方需要一条已经能用的信道。在 punch-hole 里这就是宿主的信令传输：任何能承载小块帧、有序且经过认证的信道都可以，RPC 流、WebSocket、DHT 记录都行。

库把这条信道当作不透明字节流。宿主在两端泵帧，剩下的交给打洞状态机。

## 同时打开（simultaneous open）

下面是两个锥形 NAT（地址端口过滤）之间的打洞过程：

1. 双方通过信令拿到对方的反射地址。
2. 双方在约定好的时刻，开始向对方反射地址发数据报。
3. 头几批数据报抵达对端 NAT 时，过滤规则从没见过这个来源，于是被丢弃。
4. 每一端发出的数据报同时在自己的映射里写下出站记录。A 向 B 的公网地址发过包之后，A 的 NAT 就允许从那个确切地址和端口回来的包通过。
5. 下一批交叉的包落地。洞打开了。

关键在第 4 步。过滤规则把最近的出站流量当作放行凭证，同时发包让双方在同一时刻各拿到了这份凭证。重传机制兜住时机问题，因为最早交叉的包要等双方的映射都写好状态才能落地。

## 为什么锥形对锥形容易打

锥形 NAT 给每个套接字一个固定端口，打洞套接字的反射地址在探测之后一直有效。于是每端开一个套接字瞄准对方的反射地址，走完上面的流程就通了。每端一个套接字，覆盖整个场景。

## 为什么对称 NAT 难打

对称 NAT 按目的地分配新端口。它给 STUN 探测的那个端口只服务 STUN 服务器，对端瞄准这个端口时，命中的是另一条映射，反射地址在对方写它的那一刻就过期了。

出路取决于 NAT 怎么挑端口。

有些对称 NAT 按固定步长分配，比如每次加两个端口。观察到的端口序列因此能延续到未来，对端可以瞄准那些还没诞生的端口。punch-hole 把这类 NAT 叫**易对称（EasySym）**，并从观测序列预测接下来的端口。

另一些对称 NAT 的端口分配毫无规律。预测失效，策略改为加宽覆盖：每端开很多套接字，每个覆盖端口空间的一角，同时开火，直到两侧覆盖的端口撞在一起。这就是**难对称（HardSym）**场景，这场碰撞游戏就是生日攻击，名字来自那个让"足够多次抽取后必然出现重复"的生日悖论。

## 什么情况打不通

过滤规则有最终发言权。当两个对称 NAT 都按地址端口过滤时，一个数据报想通过，前提是发送方早就向那个确切的地址端口写过包。于是双方必须在两个方向上覆盖同一对端口，命中概率随端口空间的平方下降，任何有限的包预算都趋近于零。

不对称的场景还有救：难对称对锥形时，锥形一侧先写包，对称一侧的映射随后就会放行回包。策略一章会讲怎么做到。两个都按地址端口过滤的对称 NAT 则需要中继，中继由宿主提供。

## 术语表

| 术语 | 含义 |
|---|---|
| 映射 | NAT 转换表里把一个内部流量翻译成一个公网地址端口的表项 |
| 过滤 | 决定哪些入站数据报能穿过已有映射的规则 |
| 反射地址 | STUN 服务器为某个套接字观察到的公网地址和端口 |
| 锥形 NAT | 端点无关映射，每套接字一个端口 |
| 对称 NAT | 按目的地分配，每目的地一个端口 |
| 易对称 | 带固定分配步长的对称 NAT，序列可预测 |
| 难对称 | 分配不可预测的对称 NAT |
| 连接跟踪 | NAT 的转换表，以及它的有限容量 |
| 同时打开 | 双方同时发包，让各自的映射学会放行对方 |
| 打洞 | 从一次信令协商到一条可用 UDP 通路的整个过程 |
