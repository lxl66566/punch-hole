# 架构

库分成做决策的算法层和干活的驱动层。这一章讲分层、会话生命周期、驱动打洞的引擎，以及掌管所有套接字的套接字池。

## 两个层次

算法层只处理纯值，测试不需要套接字就能驱动它：

- `nat/classify.rs`：探测观测到 NAT 类别
- `nat/predict.rs`：端口序列拟合与预测
- `strategy/mod.rs` 里的选择矩阵
- 碰撞模型，以及同时喂选择和执行的定尺寸函数

驱动层掌管套接字、定时器和任务。它把观测喂给算法层，再执行算法层的决定：

- `nat/probe.rs`：STUN 探测器
- `strategy/mod.rs` 里的打洞引擎
- `socket/`：套接字池、限速器、平台套接字选项
- `session.rs`：阶段状态机
- `signaling.rs`：信令桥与会话侧帧 IO

```text
src/
├── lib.rs         公开 API 与 crate 文档
├── config.rs      PunchConfig
├── error.rs       PunchError 与 Phase
├── report.rs      PunchReport 与分阶段统计
├── signaling.rs   信令桥（HostEnd / LibEnd）与会话帧 IO
├── msg/           信令帧与数据包及其编解码
├── nat/           探测、分类、端口预测
├── strategy/      选择、定尺寸、四个策略、引擎
├── socket/        UdpIo 与 UdpFactory、SocketPool、限速、平台选项
├── session.rs     Puncher、PunchSession、阶段状态机
├── keepalive.rs   交付后的可选心跳
└── sim/           测试专用 NAT 模拟器，位于 `test-util` 特性之后
```

依赖保持很少：`tokio` 和 `tokio-util` 负责异步 IO 与取消，`socket2` 负责平台选项，`serde` 加 `postcard` 负责帧，`rand` 负责 nonce 和脉冲抽取，`bytes` 负责桥，`thiserror` 负责错误类型。探测器需要的 STUN 子集很小，直接写在库里。

## 套接字接缝

驱动层经两个小 trait 建套接字，跳过对 tokio 的直接调用。`UdpIo` 是一个 UDP 套接字，方法都吃 `&self`，靠内部可变性工作，因为接收任务和发送方共享同一个套接字。`UdpFactory` 负责建套接字。tokio 套接字提供默认实现，`Puncher::with_factory` 接受任何别的工厂，测试模拟器和 NAT 实验室就是这样挂上来的。公开 API 交付的始终是同一种 `tokio::net::UdpSocket`。

## 会话生命周期

```text
        +----------------------------------------------------------+
        |                       overall deadline                   |
        v                                                          v
Probe -> Exchange -> Negotiate -> Punch -> Confirm -> Handover -> Done
```

**Probe** 在两侧并行。各端探测 STUN、给自己的 NAT 分类、收集自己的地址。宿主给了缓存 `NatInfo` 就整段跳过。

**Exchange** 交换证据。各端把 `NatInfo` 装进 `Hello` 帧发出，收不到对端就按节奏重发。交换同时测量信令往返时间，脉冲时间表后面要用。一侧已经认领发起方角色后又收到 `Offer`，两端一起终止，两个发起方凑不出一份双方同意的计划。

**Negotiate** 把两份 `NatInfo` 变成一份计划。发起方套用矩阵、抽 nonce、发出带策略和两侧套接字数与启动延迟的 `Offer`。启动延迟等于一个信令 RTT 加 300 毫秒余量，从应答方发出 `Accept` 那一刻起算，两边的时钟都锚定在这个共同事件上，宿主时钟偏多少都无所谓。发起方把起点提前半个 RTT，补偿 Accept 在路上的时间。应答方把套接字数钳到 `max_sockets`，拒绝超过十秒的启动延迟，用本地视角重建估算，并且在启动窗口打开前 100 毫秒为止一直重发 Accept。

**Punch 和 Confirm** 共用一个引擎和一份预算。两端执行约定的策略，通路一旦可用，三步握手立刻确认。截止时间是 `punch_timeout` 与会话整体时钟上限中较小的那个。

**Handover** 交付胜者。引擎关掉所有落选套接字、join 所有任务，会话带着报告返回套接字。

整场会话跑在 `overall_deadline` 之下，每个阶段的截止时间都在它之内。

## 引擎

引擎是单个任务，吃三路输入：套接字池接收事件、信令帧、50 毫秒一拍的 tick。打洞期间发生的一切都在对这三路输入的 `select!` 里。

每个策略编译成一个执行段列表。一个执行段写明地址族、套接字数、目标列表和时长，按顺序运行。双栈计划的执行段列表可以是一个 V6 Direct 段接一个 V4 矩阵段。依赖对端活端口的目标列表在 `PortUpdate` 到达之前保持为空。

每个 tick 做：

- 当前执行段时长结束时推进段下标
- 握手完成前按信令节奏重发本地 `PortUpdate`
- 触发扫掠，让每个套接字按轮转目标发一个 Syn
- 按 `confirm_retry` 节奏重传握手包

入站包驱动握手：

1. 对端一个 `Syn` 把本套接字标记为候选，并挣得一个 `SynAck`。每个来源每个确认窗口只回一次，重传靠窗口重置覆盖，应答门的记账上限是 1024 个键。
2. 一个 `SynAck` 说明通路双向可用。本端确认自己的套接字，用 `Confirmed` 帧向对端宣布，并打开两秒的宽限期窗口。
3. 一个 `Ack` 完成对端确认。收到最后 `Ack` 的一端立即收尾，因为最后的 Ack 证明了两个方向。

确认之后，宽限应答者继续回答对端迟到的握手包，直到对端 `Confirmed` 帧到达或宽限到期。胜出套接字交给宿主时，握手流量已经清空。

两个细节保证失败的真实性。任何握手流量出现之前的发送失败直接结束会话。握手流量出现之后的发送失败只是停掉新脉冲，因为可用通路已经存在，结果交给宽限机制裁决。这一切都在会话整体时钟上限之内，宽限期也包括在内。

## 套接字池

`SocketPool` 掌管会话开的所有套接字，按地址族分组。某个族绑定失败就保持空组，需要它的执行段自然失效。每个套接字一个接收任务，任务不做校验，把每个数据报打成事件转发，附上池内下标。事件走一条容量随 `max_sockets` 缩放的带界通道，通道满了就丢事件，每个事件都是会被重传覆盖的握手包，而阻塞的接收任务会脱离取消机制的射程。

每个出站包都要过[资源控制](resources.md)里讲的三道关。胜者选举取消接收任务、等它们退出、把胜者从组里摘走并解除共享。一个胜者，其余全关，不留任何任务。失败的会话改为整体关停池子。

## 交付后的心跳

`keepalive::spawn` 把胜出套接字放进 `Arc` 共享，每十秒发一个小心跳，宿主空闲时保住 NAT 映射。返回的 guard 在 drop 时中止任务。心跳载荷带尝试 nonce，宿主要丢弃首字节是数据面魔数、长度小于协议上限的数据报。
