# 测量 NAT

探测（Probe）阶段收集后续所有决策要读的事实。一个套接字向每个配置的 STUN 服务器索要反射地址，跨服务器的端口模式给出 NAT 分类，结果以 `NatInfo` 的形式发给对端。这一章讲探测流程、分类规则和端口预测器。

## 探测流程

探测器解析每个配置的服务器，保留解析出的每个地址作为目的地，一个主机名有多个记录就贡献多个目的地。重复的地址合并，一个目的地对应一条映射。所有目的地共用一个 UDP 套接字，探测器在一轮扇出里向每个目的地各发一个 STUN 绑定请求。

每个请求带自己的事务 id，每个应答填进自己目的地的槽位。槽位记录的是发送顺序，与到达顺序无关，而发送顺序在 NAT 上就是分配顺序。静默的目的地会进入重试轮，重试从同一个套接字发出，NAT 复用第一次的映射，发送序号保持有效。始终不应答的目的地留下一个洞：一次分配发生了，只是没人报告它的端口。

整个阶段受 `probe_timeout`（默认三秒）约束。第一轮等半份预算，重试轮等到截止。剩余时间里有一小段 IPv6 探测，收集全局地址。

## 读懂分配序列

应答端口按发送顺序组成 `alloc_seq`。它是 NAT 给这个套接字写的分配历史，一次出站流量一个端口，按创建顺序排列。三条规则把它变成类别：

- 反射地址等于本地地址：`Public`
- 序列里所有端口相同，或者应答不足两条：`Cone`
- 相邻端口按发送序号距离保持恒定步长：`EasySym { step }`
- 其余一切：`HardSym`

步长的算法是端口差除以发送序号距离，所以有洞时真实步长依然成立。序列 `5000, 5002, 5006` 里序号 2 静默，最后一段差值横跨两次分配，读出来的步长仍是 2。

一个套接字对多个目的地就足以定类。两个套接字共享一个端口可能是窄分配区间里的巧合，所以探测器只读序列，再多开一个套接字做旁证。

## 置信度

两个一致的差值可能是巧合。一次拟合要有三个差值，也就是四条以上观测，才算可信。选择阶段把不可信的 `EasySym` 降级成 `HardSym` 再挑策略，弱拟合的代价是走保底路径，而不是一场失败的打洞。

## 探测量了什么，没量什么

端口序列量的是映射。过滤没有量：区分端点无关过滤和地址端口相关过滤需要改端口请求或第三方回声，探测序列里只有绑定请求。所以探测结果里 `FilterClass` 恒为 `Unknown`，策略只消费映射类别。对称对的估算数学显式声明自己的过滤假设，策略一章会讲。

## 端口预测

`PortPredictor` 把序列变成接下来的预期端口。

- `fit` 取差值的中位数当步长，个别离群值只会让拟合弯一下，断不了。差值先归一化到带符号 16 位域，跨过端口边界的步进依然读作它代表的那个小的负步长。
- `with_step` 用一个在观测差值之外得出的步长延续序列。分类器按序号距离算出的步长能穿过洞，而带洞序列的相邻差值读起来偏宽，所以策略优先 `with_step`，`fit` 只做保底。

`window(count)` 列出最后一次观测之后的 `count` 个端口，钳制在合法端口范围内。策略把套接字瞄向这些端口。

## IPv6

IPv6 轮通过同样的 STUN 服务器收集至多八个全局地址。全局地址不需要翻译，列表里有地址就是直连候选，NAT 的问题只留给 IPv4。

## 缓存

最近打过洞的宿主可以把上一次的 `NatInfo` 交给 `Puncher::with_cached_nat`，跳过探测阶段。缓存是否新鲜由宿主判断：网络会变，一份过期的分类会带偏整场会话。构造器会把缓存值钳制到线上限内，超长的缓存撑不破信令帧。
