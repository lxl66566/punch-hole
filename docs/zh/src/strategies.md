# 打洞策略

选择逻辑读两端的 NAT 类别，从矩阵里挑一个策略。之后两端各自从自己的视角在数据面上执行同一份计划。这一章从简到繁讲四个策略，以及给重型策略定尺寸的数学。

## 选择矩阵

选择跑在**有效**类别上，意思是拟合不可信的 EasySym 在这里已经被降级成 HardSym：

| 本端 \ 对端 | 锥形或公网 | 易对称 | 难对称 |
|---|---|---|---|
| 锥形或公网 | ConeExchange | SymProbe | SymProbe |
| 易对称 | SymProbe | PredictiveExchange | BirthdayBurst |
| 难对称 | SymProbe | BirthdayBurst | BirthdayBurst |

发起方套用矩阵，把结果连同两侧套接字数和脉冲时间表装进 `Offer` 发出。应答方把套接字数钳制到自己的上限，回 `Accept`。

## Direct 执行段

矩阵策略运行前，Direct 段先看看这对 NAT 是不是根本不需要费劲。两侧都报告了全局 IPv6 地址，或两侧 IPv4 都是公网时，它会先跑。该段预算是 `direct_window`（默认一秒），从打洞预算里扣除，矩阵策略用剩下的部分。

`Hello` 里携带的地址属于发送方的探测套接字，而探测套接字那时已经关闭。所以 Direct 段和所有瞄准固定端口的执行段一样，要等对端的 `PortUpdate` 报来打洞套接字的活端口。

## ConeExchange

两端各开一个套接字，向对方反射地址发 Syn 脉冲。同时发包覆盖受限过滤，原理见打洞原理一章，之后三步握手确认通路。

## SymProbe

恰好一侧是对称 NAT。对称侧负责开火：开 `assistant_sockets` 个（默认 16）套接字，从每一个向锥形侧报来的端口发 Syn 脉冲。锥形侧开一个套接字，应答收到的每个 Syn，同时向对称对端的公网地址喷洒候选端口。

喷洒是给按地址端口过滤的锥形侧准备的。这种锥形会丢弃对称侧的脉冲，因为脉冲的来源端口它从没写过。锥形自己的喷洒先写包：一旦一发喷洒落在对称对端的活映射上，SynAck 会从对端地址带着恰好那枚候选端口回来，锥形的映射自然放行，握手经由这次命中完成。

候选端口跟随对端的有效类别：

- 可信的易对称对端拿到其观测序列的延续端口。窗口覆盖对端套接字数外加 16 的余量，余量吸收同一 NAT 背后无关的分配，窗口按分类器步长前进。
- 难对称对端拿到其观测区间上的不重复随机端口流。流长按单向模型解出 `target_success`，受包预算的一个份额和连接跟踪上限双重封顶。

对端流量出现后，喷洒每轮只发一个包，把发送速率让给握手应答。

## PredictiveExchange

两侧都是易对称。每端拟合对端序列，开 `predictive_sockets` 个（默认 8）套接字，向预测端口窗口发包。窗口覆盖两侧套接字数再放大四倍，上限 512 个端口。两侧的窗口从同一个拟合基点出发，步长成立期间保证有重叠。

## BirthdayBurst

两侧都是对称，且至少一侧是难对称。预测指望不上了，策略改打碰撞：每端开若干套接字，每个套接字覆盖从对端观测区间里抽出的不同端口，同时开火，直到两侧覆盖的端口在两个方向上撞出配对。

一个定尺寸函数同时喂决策和执行。模型假设两端都是地址相关过滤，这是 CGNAT 的常见形态，此时一个单向命中就能完成握手。每端 `n` 个套接字、覆盖 `c` 个端口，对端口空间 `space` 的命中概率是：

```text
chance = 1 - exp(-(n_A * c_A * c_B + n_B * c_B * c_A) / space)
```

覆盖率是杠杆：同样一条映射，花在更宽的覆盖集上比再开一个套接字买到的概率更多。所以定尺寸先给每端开一个套接字，覆盖率顶到上限才加套接字。上限有四个：对端可抽的端口窗口、连接跟踪上限减去应答余量、包预算的四分之一、`max_sockets`。默认配置对 32768 宽的完整空间，定出的结果是每端一个套接字覆盖 107 个端口。

端口列表由以尝试 nonce 为种子的生成器抽出，两侧独立覆盖，同一种子可复现。扫掠重复同一份覆盖集，所以每一轮的概率等于整次尝试的概率。

估算低于 `min_success` 时，协商直接以 `Unpunchable` 失败，一个数据包都还没发，绝望的组合对双方都保持廉价。

## 估算值

SymProbe 和 BirthdayBurst 会在 `PunchReport` 里报告 `success_estimate`。两端从各自的视角算出同一个值，报告因此一致。宿主读这个值来提前决策：中继是不是比继续尝试更划算。

## 模型声明过的边界

碰撞数学公开自己的假设：它假设两个对称 NAT 都是地址相关过滤。两侧都按地址端口过滤时，命中要求两个方向在确切端口上配对，概率落在 `(n * c)² / space²` 附近，有限预算买不到任何东西。预期两端都是端口严格对称 NAT 的宿主，从一开始就该规划中继。
