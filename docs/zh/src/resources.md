# 资源控制

打洞会向很多地址发很多包，一次失控的脉冲足以挤爆 NAT 的转换表或宿主的描述符。发送路径上有三道关，所有上限都来自 `PunchConfig`，每条退出路径都做清理。

## 发送路径上的三道关

每次 `SocketPool::send` 走同一个流程：

1. **连接跟踪上限。** 一个新目的地按活套接字数花映射，池子检查 `活套接字数 × 去重目的地数` 是否超过 `max_mappings`，超了就报 `ConntrackExhausted`。
2. **包预算。** 一个会话级计数器封顶数据面总发包数。发送失败会退还配额，路由不通就一分钱都不花。
3. **限速。** 一个全局令牌格保证所有池内套接字合计每秒最多 `packets_per_sec` 个包。

会话发出的每个包都过这三道关，握手应答也一样。

## 默认足迹

每个策略的默认足迹都刻意压得很小：

- BirthdayBurst 在 32768 宽的端口空间里持 108 条映射，107 个覆盖端口加对端应答端口，约占空间的千分之三。
- PredictiveExchange 持最大的默认足迹 2048 条映射，8 个套接字对 256 端口窗口，`max_mappings` 默认 4096 就是给它留的。
- SymProbe 的喷洒封顶在包预算的四分之一和连接跟踪上限减一。

## 套接字数与通道

`assistant_sockets`、`predictive_sockets`、`max_sockets` 封顶套接字数，`max_sockets` 另有 4096 的硬上限。接收任务到引擎之间的事件通道容量随 `max_sockets` 在 64 到 1024 之间缩放，Syn 应答门的记账上限是 1024 个来源键。

## 清理

每个套接字都归池子。胜者选举取消接收任务、join 它们、关闭落选者，把胜者作为独立套接字交付。失败的会话整体关停池子。宿主直接丢掉会话 future 时走池子的 `Drop`，尽力取消任务。模拟器和 NAT 实验室的观测钩子直接断言结果：交付之后，每侧恰好剩一条映射。

## 平台套接字

`socket/sys.rs` 集中处理平台差异。

- Linux 和 macOS 给辅助套接字设 `SO_REUSEADDR` 和 `SO_REUSEPORT`，加快尝试之间的重绑。
- Windows 用 `SO_EXCLUSIVEADDRUSE` 做独占绑定，因为它的 `SO_REUSEADDR` 允许两个套接字认领同一端口且投递结果未定义。辅助套接字靠彼此不同的临时端口工作。这个选项让交付出去的业务套接字免受经典的本地端口劫持。
- 胜出套接字保持原样，永不重绑，端口复用只影响快速重试的场景。

一个 connect 过的 UDP 套接字会报出操作系统将要路由走的地址。探测器用这个技巧区分公网主机和被转换的主机。
